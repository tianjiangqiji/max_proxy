## 总体目标
- 清理并修复后端（API）与前端（React）中的编译与运行时报错，统一模块导入方式，完善类型声明，确保“构建-启动-访问”全流程零报错。

## 后端修复
- 模块导入规范：在 `api/*.ts` 中统一使用带扩展名的 ES 模块导入（如 `./database/operations.js`、`./routes/auth.js`），保持与编译后 `dist/api/*.js` 一致。
- 数据库初始化与懒加载：
  - 在 `api/database.ts` 中改用 ES 模块方式导入 `fs`、`bcrypt`，移除 `require`。
  - 在 `api/database/operations.ts` 中移除模块级 `getDatabase()` 调用，所有导出函数内改为懒获取 `const db = getDatabase()`，避免“未初始化数据库”运行时错误。
- 代理中间件类型与事件：
  - 在 `api/server.ts` 内将 `http-proxy-middleware` 事件改为 `on: { proxyReq, proxyRes, error }` 结构。
  - 为 `router`、`proxyReq`、`proxyRes` 的 `req` 使用安全的类型交叉或显式类型（保持已有 `any` 但可选优化为 `IncomingMessage & Express.Request`）。
- 全局类型增强：
  - 保持 `api/types/express.d.ts` 对 `Express.Request` 的扩展（`apiKey`、`apiKeyGroup`、`targetEndpoint`、`startTime`）。

## 前端修复
- 组件导入：在 `src/components/MainInterface.tsx`、`src/components/admin/AdminDashboard.tsx` 中确保 `Label` 从 `@/components/ui/label` 正确导入。
- 副作用调用：在 `MainInterface.tsx` 中将 `useState(()=>{ fetchSystemInfo() })` 修正为 `useEffect(()=>{ fetchSystemInfo() }, [])`，消除潜在运行时问题。

## 构建与脚本
- TypeScript 配置：使用独立的 `tsconfig.api.json` 编译后端到 `dist/api`；前端保留现有 `vite build` 流程。
- NPM 脚本：
  - `build:api`: `tsc -p tsconfig.api.json`
  - `build`: 先编译 API 再执行 `vite build`
  - `start:api`: `node dist/api/server.js`
  - `dev`: 并发启动前端与后端（如需要可使用 `concurrently`）。
- 初始化脚本：`scripts/init.js` 采用 `../dist/api/database.js` 的导入路径，保证在已编译后端环境下初始化数据库。

## 验证流程
- 编译检查：
  - 后端：`npm run build:api`（应无 TypeScript 报错）
  - 前端：`npm run build`（生成 `dist/`）
- 本地启动：
  - 后端：`npm run start:api` 或 `node dist/api/server.js`
  - 前端：`npm run client:dev`（Vite 开发服务器）
- 端点验证：
  - `GET http://localhost:3001/health` 返回 `{status:'ok'}`
  - 管理：`http://localhost:3001/api/admin` 与登录接口可用（默认账号 `admin/123456`）
  - 公共接口：`GET http://localhost:3001/api/keys/info`、`GET /api/keys/query/:key` 正常
  - 代理：`POST http://localhost:3001/api/v1/*` 正常转发并记录日志
